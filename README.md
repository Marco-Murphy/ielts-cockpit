# IELTS Cockpit · 雅思冲刺舱

一个**本地运行**的雅思备考工作台。练题判分、错题归因、词汇管理、打卡追踪、进度可视化，全部在你自己电脑上跑，数据存本地 JSON 文件，不依赖任何云服务。

- **技术栈极轻**：Node 22 + Express + 原生 JS，无构建步骤、无数据库、无前端框架
- **数据完全自持**：所有记录就是 `data/` 下的几个 JSON 文件，直接复制即备份
- **手机可用**：电脑启动后，手机连同一 WiFi 即可访问，可「添加到主屏幕」当 App 用
- **可选 AI 评分**：接入任意兼容的模型 API 后，可做写作批改与口语听音评分；不接也能用全部基础功能

## 核心设计思路

市面上的雅思 App 大多解决「给你题做」，但真正卡住分数的是三件事：**不知道错在哪、不记得错过什么、不知道自己有没有在进步**。这个工具就是围绕这三件事设计的。

**1. 判分不是终点，归因才是**
每道错题都要求填一个「错误类型」（定位错 / 同义替换没认出 / 生词 / 语音现象 / 拼写 / 走神…）。错题攒到一定量后，工具会按错误类型聚合，告诉你「你最常犯的其实不是你以为的那个错」。

**2. 词汇和题目要联动**
生词不是单独背的，而是从你实际做错的题里长出来的。每个词都记着它来自哪套题、哪个 section，复习时能回到原始语境。

**3. 进步要看得见**
打卡时长、连续天数、各科 band 趋势、距目标缺口——把这些摊在首页，是因为**「感觉自己在进步」本身就需要证据支撑**，否则很容易因为一次模考失利就否定全部积累。

> 首页还有一块「动力锚」：随机显示一句学习语录 + 累计已投入时长。倒计时告诉你还剩多少，动力锚告诉你**已经存了多少**——两个方向的账一起看，心态才稳。

## 快速开始

### 环境要求

- **Node.js ≥ 22**（必须，项目用了较新的 Node API）
- 任选一个现代浏览器（Chrome / Edge / Firefox）

### 三步启动

```bash
# 1. 安装依赖（仅首次，只装 express 和 dotenv 两个包）
npm install

# 2. 可选：配置 AI 评分（不配也能用，见下文 AI 评分配置）
cp .env.example .env

# 3. 启动
npm start
```

启动后控制台会打印访问地址：

```
========================================
  IELTS Cockpit 已启动
========================================
  本机访问:   http://localhost:3000
  局域网访问（手机）:
    http://192.168.x.x:3000
----------------------------------------
```

浏览器打开 `http://localhost:3000` 即可。

**开发模式**（改代码自动重启）：

```bash
npm run dev
```

### 首次使用建议顺序

工具是空数据启动的。建议按这个顺序走一遍：

1. **设置页** → 填考试日期 + 设定四项目标分（默认是 听7/读7/说6.5/写6.5，按自己情况改）
2. **摸底** → 找一套完整真题，严格计时做完，在「练习」里录入答案并判分
3. **看总览页** → 确认 baseline 和四项缺口算出来了
4. **之后每次练题** → 录入 + 归因错题；每天在「打卡」记一笔时长

先有 baseline，后面所有趋势图和缺口分析才有意义。

## 手机访问

1. 电脑和手机连**同一个 WiFi**
2. 启动后看控制台输出的局域网地址（形如 `http://192.168.x.x:3000`）
3. **首次访问** Windows 会弹防火墙提示 → 勾选「专用网络」并允许
4. 手机 Chrome 打开该地址 → 菜单里选「添加到主屏幕」

添加后图标和体验接近原生 App，做题计时、打卡都能在手机上完成。

> 如果手机打不开：先确认没开 VPN / 代理，再确认防火墙放行。电脑 IP 变了的话重新看控制台输出。

## 功能模块详解

### 总览（Dashboard）

打开就是全局视图：

| 区域 | 内容 |
|---|---|
| 倒计时 | 距考试天数（未设日期则显示提示） |
| 动力锚 | 随机语录 + 累计投入时长 / 打卡天数 / 连续天数 |
| 今日状态 | 今天是否已打卡、做了多少分钟 |
| 四项缺口 | 各科最近 band vs 目标，红色表示还差多少 |
| 趋势 | band 随时间变化曲线 |

### 练习与判分

支持**听力**和**阅读**两个客观题的练习记录：

1. 选科目 → 选套题（如 剑18 Test 2）→ 选 section
2. 填「我的答案」和「正确答案」
3. 一键判分 → 自动算 raw 分 → 换算 band

判分规则（可在代码里调整）：
- 严格匹配，**含拼写错误判定**
- 大小写归一化（`TRUE` / `true` 视为相同）
- 数字写法归一（`10` / `ten` 视题目而定，默认严格）
- raw → band 用通用换算表近似（不同册略有差异）

**错题归因**：判错的题会进入错题本，要求你选错误类型。这是整个工具最有价值的一步——**别跳过它**。

### 词汇本

每个词包含字段：

```
word        单词
meaning     释义
type        词性
section     来源 section（听力/阅读）
source      来源套题
alternate   同义替换
basic       基础义
basicNote   基础义补充
note        笔记 / 记忆法
learned     是否已掌握
mastery     熟练度
```

可以从「今日新词」「待复习」两个入口进入，按熟练度筛选。**推荐做法**：只录那些「真的卡住你、导致你丢分或读得慢」的词，不要无差别录入——词汇本的价值在于精准，不在于数量。

### 洞察（Insights）

这是本工具区别于普通刷题 App 的地方。把你在做题中悟到的**方法论**记下来，分类为：

- `listening` 听力技巧
- `reading` 阅读技巧
- `vocab` 词汇方法
- `method` 通用方法

每条洞察有 `tag`（一句话结论）和 `content`（详细说明），并记录来源套题。攒到几十条后，这里就是你个人的战术手册——比任何网课笔记都更贴合你自己的弱点。

**写法建议**：tag 写成可执行的规则（「先给 A/B/C 贴代号再追踪代词」），content 写清楚当时是怎么想通的。

### 打卡

日历是打卡的主界面。已练习、未练习、尚未到来的日期分别用不同颜色显示；点击过去或今天的日期，可记录、补录、修改或删除学习时长、练习内容和备注。

- **日视图**：按月逐日查看；**月视图**：纵览全年各月的练习分布；**年视图**：查看多年节奏，再逐层点进具体日期
- 顶部显示连续天数、本月练习天数和累计时长

> 打卡的意义不在「连续多少天」这个数字本身，而在于它把「我今天有没有推进」这件事**从模糊感觉变成明确记录**。断签也别焦虑，记录本身就够了。

### Windows 桌面小窗

双击 [scripts/start-widget.cmd](scripts/start-widget.cmd) 可打开一个置顶的迷你学习卡片。它显示最近一次听力、阅读练到的位置，以及本周打卡天数；标题可以拖动，右上角可以收起、展开、刷新或关闭。小窗每分钟从本机的 `data/checkins.json` 刷新，不连接云服务。企鹅装饰由代码绘制，不包含动漫截图或官方素材。

### 目标模拟器

输入四项假设分数组合，即时算出总分并显示是否达标。

**雅思总分算法**：四项算术平均，四舍五入到 0.5 档，**无权重**。

```
例：听力 8 + 阅读 8 + 口语 7 + 写作 6.5 = 29.5 / 4 = 7.375 → 四舍五入 7.5
```

模拟器能帮你直观看到**短板效应**：把最强的两项各提高 0.5，往往不如把最弱的一项提高 0.5 有效。

### 设置

- 考试目标日期
- 昵称
- 四项目标 band（滑杆调整，实时显示合成总分）
- 摸底 baseline 录入

## AI 评分配置（可选）

**不配也完全能用**——练习判分、词汇、洞察、打卡、趋势全部是本地功能。

配置后可解锁：
- **写作批改**：按官方四项描述符评分 + 给出修改清单
- **口语听音评分**：直接分析录音的声学特征（发音/流利度），不是先转文字再评
- **Task 1 读图**：核对图表数据描述是否准确

### 配置方式

复制 `.env.example` 为 `.env`，填入 API key：

```bash
cp .env.example .env
```

```ini
PORT=3000

# 模型 API（以下以阿里云百炼为例，任何兼容接口均可改 baseURL 对接）
DASHSCOPE_API_KEY=sk-xxxxxxxx
LLM_MODEL=qwen-max
OMNI_MODEL=qwen3.5-omni
VISION_MODEL=qwen-vl-plus
```

模型分工：
- `LLM_MODEL` — 文本评分（写作批改）
- `OMNI_MODEL` — 多模态听音（口语发音评分，**必须能直接处理音频**）
- `VISION_MODEL` — 图像理解（Task 1 图表读图）

> **为什么口语一定要用能听音频的模型**：发音和流利度是声学特征，先转文字会把它们全部丢掉——文字的"发音评分"本质上是模型在猜。这是本项目实测后的结论。

### 评分方法论

Prompt 模板放在 `prompts/` 目录，可自行修改。核心设计：

1. **官方 band 描述符锚定** — 先给模型完整评分标准，再让它评
2. **证据优先** — 强制模型先引用原文/原音频中的具体证据，再给分
3. **每次评分开新对话** — 避免上下文污染
4. **半档辩论复核** — 对边界分数二次质询，减少虚高

## 个人档案与目标设置

存档在 `data/profile.json`：

```json
{
  "nickname": "",
  "examTargetDate": "",
  "targetCombo": { "listening": 7.0, "reading": 7.0, "speaking": 6.5, "writing": 6.5 },
  "dailyMinutes": { "min": 60, "max": 120 },
  "baseline": null
}
```

- `examTargetDate` 默认留空，**请在设置页填写**（格式 `YYYY-MM-DD`）
- `targetCombo` 是四项目标，总分由四项平均自动算出
- `baseline` 是摸底成绩，录入后缺口分析才准确

## 数据结构

所有数据都是 `data/` 下的 JSON，直接可读可改：

| 文件 | 内容 | 结构 |
|---|---|---|
| `profile.json` | 个人档案与目标 | 单对象 |
| `checkins.json` | 打卡记录 | 数组 |
| `practices.json` | 练习记录（含判分） | 数组 |
| `mistakes.json` | 错题归因 | 数组 |
| `vocab.json` | 词汇本 | 数组 |
| `insights.json` | 方法论洞察 | 数组 |
| `essays.json` | 写作批改记录 | 数组 |
| `speakings.json` | 口语评分记录 | 数组 |
| `reports.json` | 周报 | 数组 |

**存储机制**：内存缓存 + 防抖写盘（500ms）+ 原子写（先写临时文件再重命名）。启动时会自动把现有数据备份到 `data/backup/`。

想手动加数据，直接编辑 JSON 后重启服务即可。

## 备份与迁移

**备份**：复制整个 `data/` 目录。

```bash
npm run backup
```

**迁移到另一台机器**：

1. 把整个项目目录拷过去（`node_modules/` 可不拷，重新 `npm install`）
2. 把 `data/` 一并拷过去
3. `npm install && npm start`

**注意**：`.env` 含 API key，属于敏感信息，不要提交到版本库（`.gitignore` 已默认排除）。

## 常见问题

**Q：启动报 `EADDRINUSE`**
端口被占用。通常是已经启动过一个实例了——先去 `http://localhost:3000` 看看是不是已经开着。要换端口就在 `.env` 里改 `PORT`。

**Q：手机打不开局域网地址**
① 确认同一 WiFi；② 关掉电脑和手机的 VPN / 代理；③ 检查 Windows 防火墙是否放行了 Node；④ 确认电脑 IP 没变（重新看控制台输出）。

**Q：判分结果和官方答案不一致**
换算表是通用近似表，不同册次略有差异。可在设置页手动修正 band，或直接改代码里的换算逻辑。

**Q：数据会不会丢**
写盘是原子操作（写临时文件 + 重命名），中途崩溃不会写坏文件。启动时还会自动备份。但**没有任何云同步**——请定期把 `data/` 复制到别处。

**Q：可以多设备同时用吗**
不建议。数据存本地文件、走内存缓存，两端同时写会互相覆盖。要么固定用一台，要么手动同步 `data/` 目录。

**Q：能部署到公网吗**
架构上是本地优先设计的。要部署需要把 JSON 文件存储换成真正的数据库（建议换 SQLite 并处理并发写），前端可直接复用。

**Q：支持哪些题型**
目前客观题支持听力、阅读的填空/选择/判断等常见题型。写作和口语需要配置 AI 评分后使用。

## 二次开发

**加一个页面**：在 `public/js/pages/` 新建模块，在 `public/js/app.js` 注册路由。

**加一个 API**：在 `server/routes/` 新建路由文件，在 `server/index.js` 挂载。

**加一个数据集合**：在 `server/config.js` 的 `dataFiles` 里加一行映射（如 `essays: 'essays.json'`），存储层会自动处理读写、备份与原子写。

**改评分逻辑**：`prompts/` 下是 prompt 模板，`server/services/` 是调用逻辑，`server/routes/score.js` 是 band 换算表。

代码风格：纯 JS 无 TypeScript，无构建工具，改动保存后刷新浏览器即可生效（后端改动需重启，或用 `npm run dev`）。
